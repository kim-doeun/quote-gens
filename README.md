# Lomin 견적서 발급 및 관리 시스템

Lomin(로민) 회사의 영업대표들을 위한 **견적서 발급 시스템**이자, 회사 전체의 **견적 이력 관리 시스템**입니다. 프론트엔드(HTML/CSS/JS)와 자체 RESTful Table API 백엔드(Node.js + SQLite)로 구성되며, Docker로 온프레미스 환경에 배포합니다.

---

## 1. 프로젝트 목표

- 영업대표가 고객사별로 신속하게 **표준화된 견적서**를 발급
- 견적서를 **S/W 라이선스(제품)** 와 **개발비(서비스/인건비)** 두 축으로 명확히 구분해 산정
- 회사가 모든 **견적 발행 이력을 검색·필터·상태관리**
- S/W 라이선스 카탈로그, 인건비 등급별 단가표, 고객사 정보를 재사용해 입력 효율 향상
- 발행된 견적서를 실제 견적서 양식(예시 이미지)과 동일한 형태로 **화면 확인 및 인쇄/PDF 저장**

---

## 2. 완료된 기능

### 🧭 공통 레이아웃 - 좌측 메뉴(사이드바)
- 모든 페이지 좌측 사이드바(`js/common.js`의 `renderSidebar`)는 **접기/펼치기(collapse) 가능**합니다.
- 데스크톱(1024px 이상)에서는 사이드바 우측 상단에 원형 토글 버튼이 표시되며, 클릭 시:
  - **펼침 상태**: 로고, 회사명, 메뉴 라벨이 모두 표시되는 기존 레이아웃 (너비 16rem)
  - **접힘 상태**: 아이콘만 남고 텍스트 라벨은 숨겨지는 좁은 레이아웃 (너비 5rem), 각 메뉴에 `title` 툴팁 제공
- 접기/펼치기 상태는 `localStorage`(`lomin_sidebar_collapsed`)에 저장되어 **페이지를 이동하거나 새로고침해도 유지**됩니다.
- 모바일/태블릿(1024px 미만)에서는 토글 버튼이 숨겨지고, 기존처럼 사이드바가 상단에 항상 펼쳐진 상태로 표시됩니다(레이아웃에 영향 없음).

### 📊 대시보드 (`index.html`)
- 전체 견적서 수, 이번 달 발행 금액, 승인된 견적 수, 진행중 견적 수 요약 카드
- 최근 6개월 월별 발행 금액 바 차트 (Chart.js)
- 상태별 견적 분포 도넛 차트
- 최근 발행 견적서 리스트 (클릭 시 상세 이동)

### 📝 견적서 발급 (`quote-new.html`)
- **견적서 기본 정보**: 견적명(프로젝트명), 참조(선택 입력) 입력
- 등록된 고객사 선택 시 담당자/연락처/이메일/주소 자동 입력 (직접 입력도 가능)
- 견적담당(영업대표) 정보 입력 (이름/이메일/연락처)
- **발급상태 지정 필드 없음** — 견적서는 항상 저장 시 `발송전` 상태로 생성되며, 상태 변경은 발급 이후 「견적 이력 관리」 화면에서만 수행하며, 견적서 문서(인쇄/PDF 포함)에는 전혀 노출되지 않습니다.
- 견적 항목을 **4개 섹션으로 분리 입력**, 각 섹션은 항상 고정으로 표시됩니다(동적으로 표가 생성/제거되지 않음):
  - **01. S/W 라이선스** — 등록된 S/W 라이선스 카탈로그에서 선택하거나 직접 입력. 항목/설명/구분(운영·개발)/수량(Q)/소비자단가(LP)/소비자금액(Q×LP)/제안단가(P)/제안금액(Q×P)/비고
  - **02. 개발비** — 등록된 인건비 단가표(등급별)에서 선택하거나 직접 입력. 업무활동/설명/등급(특급·고급·중급·초급)/수량(M/M, 인월 단위 소수 입력 가능)/소비자단가(LP)/소비자금액(M/M×LP)/제안단가(P)/제안금액(Q×P)/비고
  - **03. 하드웨어** — 하드웨어 품목을 자유롭게 추가하는 고정 섹션입니다. 「+ 항목 추가」 버튼을 누르면 모달이 열리고(01/02와 동일한 UX), 항목명/구분(운영·개발)/설명/수량/소비자단가/할인율 또는 제안단가/비고를 입력해 추가합니다. 표 컬럼 구조는 01. S/W 라이선스와 완전히 동일합니다: 항목/설명/구분/수량(Q)/소비자단가(LP)/소비자금액(Q×LP)/제안단가(P)/제안금액(Q×P)/비고
  - **04. 기타** — 03. 하드웨어와 동일한 UX·컬럼 구조를 가진 별도의 고정 섹션으로, 3rd-party S/W·외주 등 하드웨어로 분류하기 애매한 기타 품목을 자유롭게 추가합니다.
  - (과거 방식과의 차이) 이전에는 "기타 품목" 섹션 하나에서 유형(하드웨어/3rd-party S/W/외주/기타)을 select로 선택해야 그 유형의 표가 동적으로 생성되었으나, 현재는 유형 선택 단계 없이 03. 하드웨어/04. 기타 두 섹션이 항상 화면에 표시되며 각각 독립적으로 항목을 추가합니다.
- 우측 요약 패널에서 S/W 소계, 개발비 소계, 하드웨어 소계, 기타 소계, 공급가액, 부가세(율 조정 가능), 총 합계금액을 실시간 계산
- 결제조건, 고객 공개용 비고, 내부 전용 메모(비공개) 입력
- 견적번호 자동 생성 규칙: `QT-{연도}-{월}-{3자리 순번}` (예: `QT-2026-08-001`, 연/월별로 순번 초기화)
- 견적담당(영업대표) 정보는 「영업대표 관리」 화면에 등록된 목록에서 select로 선택하면 이름/이메일/연락처가 자동 입력되며(고객사 선택과 동일한 UX), 직접 입력도 가능합니다.
- 고객사 선택은 회사명/담당자명으로 실시간 검색되는 팝오버 목록으로 제공됩니다(방향키 이동 + Enter 선택 지원). 목록에는 "회사명 (담당자명)"이 함께 표시됩니다.
- **URL 파라미터로 진입 모드가 달라집니다**(3절 표 참고):
  - `?id={견적ID}` — **수정 모드**: 「견적 이력 관리」에서 `발송전` 상태인 견적서만 진입 가능. 기존 견적번호를 유지한 채 내용을 그대로 갱신(같은 레코드에 덮어씀)
  - `?reviseFrom={견적ID}` — **재발행 모드**: 견적서 상세 화면의 "새 버전으로 재발행" 버튼에서 진입. 기존 내용을 불러오되 저장 시 새 견적번호로 별도 레코드를 생성하고 원본은 `재발행됨` 상태로 자동 전환(4절 "버전 관리(재발행)" 참고)
  - 파라미터가 없으면 일반 신규 발급 모드
- 저장 시 `quotes`(헤더 + 소계) 및 `quote_items`(항목, `item_type`으로 제품(S/W라이선스)/서비스(개발/구축)/하드웨어/기타 구분) 테이블에 함께 저장
- **견적서 저장(발급) 완료 시 Slack 채널 알림 자동 발송** (`js/common.js`의 `notifySlackQuoteIssued`)
  - Slack **Incoming Webhook** 방식 사용 (지정된 하나의 채널에만 새 메시지로 게시 — 스레드 답글 아님)
  - 알림에 포함되는 정보: 견적번호, 고객사명, 견적명, 총 제안 금액(VAT 포함), 담당자, 견적서 상세 페이지 바로가기 링크
  - 알림 전송은 저장 성공 이후 비동기로 수행되며, 전송 실패 시에도 견적서 저장/화면 이동에는 영향 없음(콘솔에 에러만 로그)
  - ⚠️ 보안 참고: 정적 사이트 특성상 Webhook URL이 클라이언트 JS 코드에 노출됩니다. 해당 URL은 지정된 채널에만 메시지를 게시할 수 있는 제한된 권한이므로 상대적으로 안전하지만, 유출이 우려되는 경우 Slack에서 Webhook을 재발급(무효화)하고 코드를 갱신해야 합니다.

### 📁 견적 이력 관리 (`quotes.html`)
- 견적번호/고객사/영업대표 통합 검색
- 상태별, 영업대표별 필터 및 발행일/금액 정렬
- 검색 결과 건수 및 합계 금액 실시간 표시
- 목록에서 바로 상태 배지 클릭 → 상태 변경 모달 (발송전/발송됨/내부협의중/계약됨/만료됨/재발행됨)
- 상세보기, 삭제(소프트 삭제) 지원
- 재발행(새 버전)으로 생성된 견적은 견적번호 옆에 `v2`/`v3` 같은 버전 배지가 표시됩니다(아래 "버전 관리(재발행)" 참고)

### 📄 견적서 상세/인쇄 (`quote-detail.html?id={견적ID}`)
- 첨부 예시 이미지와 동일한 형식의 정식 견적서 문서 레이아웃:
  - Lomin 로고 + 상단 **견적 정보표** (예시 이미지와 동일한 표 형식): 견적명 / 수신 / 참조 / 연락처(고객) — 견적담당 / 연락처 / 이메일(영업대표) — 사업자등록번호 / 회사명 / 대표이사 / 주소 / 대표전화(Lomin 고정 정보)
  - 견적번호 / 발행일 / 유효기한 요약 카드 (상태는 표시되지 않음 — 내부 관리 전용)
  - **「01. S/W 라이선스」** 표 (항목/설명/구분/수량Q/소비자단가LP/소비자금액Q×LP/제안단가P/제안금액Q×P/비고) + S/W 제안 금액(VAT 제외/포함) 소계 바
  - **「02. 개발비」** 표 (업무활동/설명/등급/수량M-M-Q/소비자단가LP/소비자금액MM×LP/제안단가P/제안금액Q×P/비고) + 개발비 제안금액(VAT 제외/포함) 소계 바
  - **「03. 하드웨어」** / **「04. 기타」** — 각각 독립된 고정 섹션으로, `quote_items.item_type`이 `하드웨어`/`기타`인 항목만 필터링해 하나의 표로 렌더링합니다. 표 컬럼 구조는 01. S/W 라이선스와 동일(항목/설명/구분/수량Q/소비자단가LP/소비자금액Q×LP/제안단가P/제안금액Q×P/비고) + 섹션별 소계(VAT 제외/포함) — 해당 섹션에 항목이 없으면 섹션 자체가 표시되지 않음
  - 최종 **「총 제안 금액」** 박스 (VAT 제외 / VAT 포함 금액을 강조 표시)
  - 결제조건, 비고
- **견적 상태는 견적서 문서(화면/인쇄/PDF)에 표시되지 않습니다.** 화면 상단의 상태 드롭다운(`no-print` 영역)으로만 내부 관리하며, 변경 즉시 반영됩니다.
- 브라우저 인쇄 기능으로 PDF 저장/출력 (`window.print()`, 인쇄 시 사이드바 등 UI 숨김)
- 내부 메모는 화면에서만 노출, 인쇄물에는 출력되지 않음
- 견적서 삭제
- **버전 관리(재발행)** — 하나의 사업(동일 고객사)에 대해 협상 중 견적서가 여러 번 발행되는 경우를 위한 명시적 버전 연결 기능:
  - 화면 상단 "새 버전으로 재발행" 버튼 클릭 시 `quote-new.html?reviseFrom={견적ID}`로 이동, 현재 견적 내용(고객/견적담당/항목/결제조건/비고 등)을 그대로 불러와 자유롭게 수정할 수 있습니다.
  - 저장하면 **기존 견적을 덮어쓰지 않고** 새 견적번호·새 발행일/유효기한으로 완전히 새 견적서가 생성되며(`parent_quote_id`로 원본과 연결, `version`은 원본 `+1`), 원본 견적은 저장 성공 직후 상태가 자동으로 `재발행됨`으로 전환됩니다.
  - 이미 `재발행됨` 상태인 견적서는 재발행할 수 없으며(더 최신 버전에서 진행하도록 안내), 상세 화면에 "버전 히스토리" 박스가 표시되어 같은 건의 모든 버전을 오가며 확인할 수 있습니다.
  - `재발행됨` 상태의 견적은 **대시보드 집계(상태별 건수/금액, 월별 차트, 최근 견적서)에서 자동으로 제외**되어, 같은 건이 여러 번 재발행되어도 건수·금액이 중복으로 부풀려지지 않습니다(최신 버전만 집계에 반영). 반면 「견적 이력 관리」 화면은 전체 히스토리를 그대로 보여주는 것이 목적이므로 기본적으로 모든 버전이 표시되며, 상태 필터에서 `재발행됨`으로 따로 걸러볼 수 있습니다.
- **엑셀(.xlsx) 다운로드 — 템플릿 기반**: 화면 상단 "엑셀 다운로드" 버튼 클릭 시, 미리 정의된 엑셀 템플릿(레이아웃/색상/테두리/로고 등 서식 고정)에 실제 견적 데이터를 채워 넣어 `.xlsx` 파일로 즉시 다운로드
  - **ExcelJS**(CDN 라이브러리) 사용, 서버 없이 클라이언트에서 파일 생성
  - **템플릿과 데이터 로직이 분리된 구조**:
    - `js/quote-excel-template.js` — "템플릿" 정의 파일. 문서 전체 레이아웃(로고 배치, 헤더 배너, 견적정보표, 항목표 헤더/바디/소계, 총액 박스, 결제조건·비고, 하단 안내문)과 모든 서식(배경색/테두리/폰트/정렬/컬럼너비/셀 병합)을 함수 단위로 정의. 서식만 변경하려면 이 파일만 수정하면 됨.
    - `js/quote-detail.js`의 `exportQuoteToExcel()` — 템플릿의 `buildQuoteWorkbook(quote, items)`를 호출해 워크북을 완성한 뒤, Blob으로 변환해 다운로드 트리거만 담당

## 5. 기술 스택

- HTML5 + Tailwind CSS(CDN) + 공통 CSS(`css/style.css`)
- Vanilla JavaScript (모듈 없이 페이지별 스크립트로 분리: `js/common.js`, `js/dashboard.js`, `js/quote-new.js`, `js/quotes.js`, `js/quote-detail.js`, `js/quote-excel-template.js`, `js/customers.js`, `js/products.js`, `js/labor-rates.js`, `js/sales-reps.js`)
- Chart.js (대시보드 차트)
- Font Awesome (아이콘)
- **백엔드**: `server/`의 Node.js(Express) + SQLite(`better-sqlite3`)로 구현한 자체 RESTful Table API (`tables/{table}`)로 CRUD. 원래 GenSpark Hosted Deploy가 제공하던 Table API(D1 기반)를 그대로 대체하도록 동일한 요청/응답 형식을 구현했으며, `.tables/schema.json`을 기준으로 테이블을 자동 생성합니다.
- **배포**: Docker / Docker Compose 기반 온프레미스 배포 (아래 8절 참고)

## 6. 아직 구현되지 않은 기능 / 제한사항

- **로그인/권한 관리**: 현재는 별도 인증 없이 모든 방문자가 전체 기능에 접근 가능합니다. 자체 백엔드(Express)가 생겼으므로 세션/JWT 기반 로그인을 서버에 직접 추가하거나, 리버스 프록시 단에서 사내망/VPN 제한 또는 기본 인증(Basic Auth)을 적용할 수 있습니다.
- **이메일 발송**: 견적서를 고객에게 이메일로 직접 발송하는 기능은 없습니다. 백엔드가 생겼으므로 향후 이메일 API(SMTP 등) 연동을 서버 쪽에 추가하는 것이 가능하지만, 현재는 구현되어 있지 않습니다. 인쇄/PDF 저장 후 수동 발송을 권장합니다.
- **전자서명/승인 워크플로우**: 고객의 온라인 서명, 내부 결재선 등의 워크플로우는 없습니다.
- **다중 통화**: 원화(KRW) 기준으로만 계산됩니다.
- **수정 이력**: 「견적서 수정」(발송전 상태에서 내용을 직접 고치는 것)은 이전 값을 보관하지 않고 현재 값만 유지합니다. 협상 중 재발행되는 케이스는 "새 버전으로 재발행"(4절 참고)으로 버전을 남길 수 있지만, 이는 매 수정마다 자동으로 히스토리가 쌓이는 범용 감사 로그(audit log)는 아닙니다.

## 8. 배포 (온프레미스 Docker)

이 프로젝트는 더 이상 GenSpark Hosted Deploy(Table API/D1)에 의존하지 않습니다. `server/` 디렉터리의 Node.js(Express) 서버가 정적 프론트엔드 파일과 RESTful Table API를 함께 서빙하며, 데이터는 SQLite 파일(`better-sqlite3`)에 저장됩니다.

### 8.1 빠른 시작

```bash
# 1) 환경변수 설정 (Slack Webhook 등)
cp .env.example .env
# .env 파일에 SLACK_WEBHOOK_URL 등을 채워 넣습니다 (선택 사항).

# 2) 빌드 및 실행
docker compose up -d --build

# 3) (선택) 최초 실행 시 샘플 데이터 채우기 — 테이블이 비어 있을 때만 삽입되어 안전합니다.
docker compose exec app node server/seed.js
```

브라우저에서 `http://localhost:3000` (또는 `.env`의 `APP_PORT`)으로 접속합니다.

### 8.2 구성 요소

| 구성 | 설명 |
|---|---|
| `server/index.js` | Express 앱 진입점. 정적 파일(`html`/`css`/`js`/`images`)과 `/tables/*`, `/api/slack/*` API를 서빙 |
| `server/db.js` | `.tables/schema.json`을 읽어 SQLite 테이블을 자동 생성 |
| `server/routes/tables.js` | GenSpark Table API와 동일한 요청/응답 형식(GET/POST/PATCH/DELETE, `{ data: [...] }` 등)의 범용 CRUD 라우터 |
| `server/routes/slack.js` | 견적서 발급 알림을 Slack Incoming Webhook으로 전송하는 서버 프록시 |
| `server/seed.js` | 빈 테이블에만 샘플 데이터를 채우는 멱등(idempotent) 시드 스크립트 |
| `Dockerfile` / `docker-compose.yml` | 컨테이너 빌드 및 실행 정의. SQLite 데이터는 `lomin-quote-data` 볼륨(`/data/app.db`)에 영속 저장됨 |

### 8.3 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 컨테이너 내부 서버 포트 |
| `DB_PATH` | `/data/app.db` | SQLite 데이터베이스 파일 경로 (볼륨 마운트 대상) |
| `SLACK_WEBHOOK_URL` | (없음) | 견적서 발급 알림용 Slack Incoming Webhook. 비워두면 알림을 보내지 않음 |
| `APP_PORT` | `3000` | (docker-compose 전용) 호스트에 노출할 포트 |

### 8.4 보안 참고

- 기존에는 Slack Webhook URL이 `js/common.js`에 하드코딩되어 브라우저(및 git 저장소)에 그대로 노출되었습니다. 이제는 서버 환경변수(`SLACK_WEBHOOK_URL`)로만 관리되며, 브라우저는 `/api/slack/notify-quote`로 견적 요약 정보만 전달합니다.
- **⚠️ 이 저장소의 git 히스토리에는 과거 커밋에 포함되었던 실제 Webhook URL이 남아 있습니다.** 저장소를 공개하거나 외부와 공유하기 전에 Slack에서 해당 Webhook을 반드시 재발급(무효화)하세요.
- `server/index.js`는 `server/`, `.git/`, `.tables/`, SQLite 데이터 디렉터리를 정적 서빙 대상에서 제외하고 `html`/`css`/`js`/`images`만 노출합니다.
- 로그인/권한 관리는 여전히 구현되어 있지 않습니다(6절 참고). 사내망 접근 제한이 필요하면 리버스 프록시(Nginx 등) 앞단에 인증을 추가하는 것을 권장합니다.

### 8.5 데이터 백업/복원

SQLite 파일 하나(`lomin-quote-data` 볼륨의 `app.db`)가 전체 데이터입니다.

```bash
# 백업
docker compose exec app sh -c 'cat /data/app.db' > backup.db

# 복원 (컨테이너 정지 후 볼륨에 파일을 덮어쓰기)
docker compose down
docker run --rm -v quote-gens_lomin-quote-data:/data -v "$(pwd)":/backup alpine \
  cp /backup/backup.db /data/app.db
docker compose up -d
```
